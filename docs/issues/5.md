# Feature request: Start the picker on the window raised before the last one

## Summary

At picker open, swap the first two entries of the already recency-sorted
window list (display only, cache untouched) so the cursor starts on the
window raised just *before* the last one.

## Motivation

The picker spawns in a fresh Alacritty window (its own window is filtered
out of the list, see `README.md`). From there, the user most likely wants a
window they were working on before, not the one they raised last.

- Raised A then B: sorted list is B, A; we want A, B, so Enter switches back
  to A instead of re-raising B.
- Raised A, B, C: sorted list is C, B, A; we want B, C, A, so Enter switches
  to B instead of back to C.

## Proposed behavior

- Keep the current recency sort (cache-backed, alphabetical tie-break,
  no-history windows last, see docs/issues/1.md).
- Swap elements 0 and 1 before rendering; cursor sits on row 0.
- View-only: no change to the cache or what `raiseAndExit` logs.

## Edge cases

- Fewer than two windows: no swap, list unchanged.
- Two windows: classic A/B toggle (picker shows A, B after raising B, and
  B, A after raising A).
- Raising the same window twice in a row: titles are unique, so the
  previous distinct window still ends up in row 0.

## Acceptance criteria

- Raise A, then B: picker shows A, B, cursor on A; Enter raises A.
- Raise A, B, C (C last): picker shows B, C, A, cursor on B; Enter raises B.
- Filters preserve the swapped order (row 0 stays first among its visible
  subset).
- `-info` and cache contents are unaffected.
