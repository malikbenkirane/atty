# Feature request: Introduce cache and sorting by most recently seen window titles

## Summary

Add a persistent cache of window access history so that the list of windows
in the UI can be sorted by "most recently seen" (i.e., the window the user
last focused/interacted with appears first), rather than the current default
ordering.

## Motivation

- Users typically switch between a small set of windows repeatedly. Sorting by
recency would put the most relevant windows at the top without typing a query.
- Without persistence, recency information is lost every time the app exits, so
the ordering doesn't improve over time.

## Proposed behavior

- Every time a window title (or window) is seen, record a timestamp in a local
cache (e.g. SQLite in a user cache dir).
- In the picker/UI, sort windows by that "last seen" timestamp, descending; fall
back to the existing sort order for windows with no cached history.
