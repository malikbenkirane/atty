# Window selectors can target a different window than the one picked

## Summary

The raise and close AppleScript selectors resolve the target window by
matching on window name alone, so when two windows share the same title
(or one title contains another), AppleScript may raise or close a window
other than the one selected in the picker.

## Problem

An earlier implementation matched with `name contains %q` in raiseScript
and closeScript, which could systematically pick the wrong window when a
picked title was a prefix of another window's title (e.g. `vim` vs
`vim ~/docs`).

A partial fix is already in place (main.go:28-33): both scripts now use
`name is %q`. `first window whose name is ...` still picks an arbitrary
one among duplicate titles (documented as unspecified ordering), so
`Enter` can raise the wrong window and close can close the wrong one.
The exact-match variant also fails to resolve stale titles
(note docs/issues/9.md).

Failure modes:

- Two Alacritty windows opened in the same directory with the same shell
  title have identical names.
- Titles that change (cd, ssh, running a command) between listing and
  raising: the name no longer exists and the raise silently targets
  nothing, or a newly-titled window whose name matches an old entry.

## Proposed fix

- Resolve the concrete `AXUIElement` window once at pick time (or keep a
  stable id attribute alongside the title, e.g. `AXTitle` plus
  `... of every window` indices captured in the list pass) and raise/close
  by reference, not by re-matching on name.
- Fallback if that is too invasive: on close, raise the matched window
  first and verify its title, or disambiguate ties by window order
  (`windows of process` index captured alongside the name).
- Fallback path on ambiguity is tracked in #9: exact match first, guarded
  `contains` fallback only for unambiguous stale titles.
- Keep current behavior for unique titles; the change only affects the
  ambiguous path.

## Acceptance criteria

- Two windows with identical titles: picker raises/closes the one whose
  row was selected (verifiable by different visible content).
- Title A being a strict prefix of title B: selecting A never raises/closes
  B.
- Window closed externally between listing and selecting: picker reports an
  error instead of closing another window.
