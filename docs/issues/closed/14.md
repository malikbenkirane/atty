# `-execute` from terminal-notifier fails to run `atty` (atty not in PATH)

Running `tty -execute` from [terminal-notifier](https://github.com/julienXX/terminal-notifier) (`terminal-notifier -title 'build done' -execute atty -title 'my shell'`) fails.

## Hypothesis (unconfirmed)

The command fails, but we have not yet isolated the root cause. The most likely suspect is `PATH`: terminal-notifier launches its target process outside an interactive shell, so the process does not inherit the shell's `PATH`, which typically includes user-local install locations such as `~/go/bin`, `~/.local/bin`, or Homebrew's `/opt/homebrew/bin`. If `atty` is installed in one of these locations, terminal-notifier cannot resolve `atty` by name.

This needs to be verified (e.g. try `-execute` with the absolute `atty` path and see whether it succeeds) before treating the proposal below as the actual fix.

The picker-less `-title` mode is exactly the mode intended for such external invocations, so it must work when executed outside a login shell.

## Proposal (if the hypothesis holds)

Before handing anything to terminal-notifier (`-execute`), resolve `atty` to its absolute path and pass that instead of the bare command name. Concretely:

- At startup, resolve the running binary to an absolute path (`os.Executable()` normalized with `filepath.EvalSymlinks`).
- When composing or documenting `-execute` invocations, always emit the absolute `atty` path so terminal-notifier does not depend on `PATH`.

Fallback diagnostic: if `atty` cannot be located, print a clear error on stderr telling the user to either add `atty`'s directory to `PATH` or pass the absolute path explicitly.

## Acceptance criteria

- [ ] The PATH hypothesis is confirmed or ruled out by testing `-execute` with the absolute `atty` path.
- [ ] `terminal-notifier -execute <absolute-path-to-atty> -title "foo bar"` raises the matching window, even though terminal-notifier's environment has a minimal `PATH`.
- [ ] `atty` resolves its own absolute path at runtime (`os.Executable` + `filepath.EvalSymlinks`) and exposes/composes accordingly.
- [ ] Documented usage (README) shows the `-execute` invocation using the absolute `atty` path.
- [ ] Failure to locate `atty -title` output produces a non-zero exit and a clear stderr message rather than a silent no-op.
- [ ] Interactive mode (`atty` without flags) behavior is unchanged.
