# Prettify window titles: collapse home directory to `~`

## Summary

Window titles often contain full absolute paths that repeat the user's home
prefix over and over, for example:

```
crush /Users/bob/some/path
```

Every window in the list repeats `/Users/bob/...`, which is redundant
information the user already knows, and adds mental overload when scanning
the picker.

Collapsing the home directory prefix to `~` shortens titles and removes the
repetitive noise:

```
crush /Users/bob/some/path -> crush ~/some/path
```

## Proposed behavior

- When displaying a window title in the interactive picker, replace a leading
  path equal to the user's home directory with `~`.
- Replacement applies only at the start of a path-like segment, to avoid
  mangling titles that merely contain `/Users/bob` mid-string.
- Only the **displayed** title is transformed: the value passed to
  `-title`, history matching, and recency keys must keep using the original
  title so existing aliases and keybindings keep working.

## Acceptance criteria

- [ ] A title like `crush /Users/bob/some/path` displays as `crush ~/some/path`.
- [ ] Titles not starting with the home prefix are displayed unchanged.
- [ ] `-title "crush /Users/bob/some/path"` still matches on the original, untransformed title.
- [ ] History entries store/compare the original title.
- [ ] Works regardless of the actual username (use `$HOME`, not a hardcoded `/Users/...`).
